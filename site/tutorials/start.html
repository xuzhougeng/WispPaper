教程 01　·　收集

从一个课题开始：检索、导入、筛选

导师给了一个方向「植物单细胞转录组」，手里一篇文献都没有。这一篇从一个空的 Wisp Study 开始：配置模型，建库，让助手拟检索式，从 PubMed 和 Europe PMC 导入 355 篇，由助手逐篇读过摘要给出建议，最后由你确认收不收。

场景
刚接手一个课题，要在一个下午里攒出第一批文献，并分出哪些值得读。
需要
Wisp Study 和一个你自己的模型服务（Claude API、OpenAI 兼容或 OpenAI Responses 接口）。
用时
约 15 分钟，其中等模型和数据库约 8 分钟。

本篇

  1. 安装，配置模型
  2. 新建文献库，写下主题
  3. 让助手拟检索式
  4. 保存并导入
  5. 让助手筛选
  6. 确认收录判断
  7. 回顾

1安装，配置模型

从发布页下载：macOS 是 .dmg，打开后把 Wisp Study 拖进「应用程序」；Windows 有安装版 -setup.exe（装在当前用户名下，不需要管理员权限）和便携版 .zip。拟检索式和筛选都要调用模型，Wisp Study 不自带模型，先在设置里接上你自己的。

点首页右上角的「设置」（⌘ + ,，Windows 上是 Ctrl + ,），进入「AI」。「模型」一栏左边是模型服务，DeepSeek、Kimi、GLM 已经列着，各标着「缺 API Key」；用其中一家，点开它填上 API Key 即可。用别的服务就点「添加服务」，从列表里选，或选「其他 OpenAI 兼容服务」：

  • 接口：Claude API、OpenAI 兼容、Responses 三选一。
  • 服务地址：OpenAI 兼容的服务写到 /v1。
  • API Key：留空则读对应的环境变量，例如 OPENAI_API_KEY。
  • 模型：在「模型」下的空白框里填服务要求的模型名称，点「添加」。一个服务可以放几个模型，每个模型有自己的思考档位。

没有保存按钮，改了就存。服务名下的「缺 API Key」换成了模型的个数，就可以用了。

一个模型就够走完全程。这次多做了两件事：在「任务」里把「翻译」交给一个把思考调低的小模型；把「同时阅读的篇数」从默认的 3 调到 8，筛选时同时发出这么多请求，服务限速时调小。

注意API Key 以明文保存在本机的 settings.json 里。用到模型时，主题、检索要求和文献的摘要会发给你配置的模型服务。

2新建文献库，写下主题

回到首页，点「新建文献库」（⌘ + ⇧ + N）。名称写「植物单细胞转录组」。主题不只是备注：助手拟检索式、判断收录、回答问题时都会读到它，所以值得写具体。这次写的是：

主题

植物单细胞与单核转录组测序（scRNA-seq / snRNA-seq）：各物种和器官的细胞图谱、发育轨迹与细胞命运、环境胁迫响应，以及原生质体制备、细胞类型注释、跨物种整合等方法学问题。

点「创建」后，页面问从哪里开始。文献已经在 Zotero 或导出文件里，选「导入已有的文献」或「从 Zotero 导入」，见教程 03。这里手里什么都没有，选推荐的「从检索文献开始」。

3让助手拟检索式

主题已经填进输入框，可以再改。下面一排是数据库：PubMed 默认选中，再加选 Europe PMC，它收预印本，这个领域的新工作常先发在 bioRxiv。Crossref 和 arXiv 对这个主题帮助不大，不选。

点「拟检索式」。大约一分钟后，助手为每个数据库各拟了三条取向不同的检索式：一条宽的，一条聚焦图谱、发育与胁迫，一条从制样和注释等方法学角度。每条下面是它立刻试检索的结果：数据库里一共命中多少篇，最新的几篇是什么。

这次试检索的命中数：

表 1　六条检索式试检索的命中篇数。
数据库宽检索图谱、发育与胁迫方法学
PubMed1007520205
Europe PMC1212635247

看标题，不看检索式写得漂不漂亮。方法学那条命中的几乎都是 single-cell、single-nucleus 开头的植物研究。试检索不往文献库里写任何东西；不满意可以改主题后点「重新拟」，或者点「自己写检索式」。这次选了两条：PubMed 的方法学检索式，Europe PMC 的图谱、发育与胁迫检索式。点「选用」，按钮变成「已选用」。

4保存并导入

点右下角的「保存并导入所选的 2 条」。两条检索式保存到「检索与导入」页并立即运行，约 40 秒：

  • PubMed：命中 205 篇，取回 200 篇，新增 200 篇。
  • Europe PMC：命中 635 篇，取回 200 篇，新增 155 篇，跳过已有的 45 篇。两个数据库有重叠，Wisp Study 按 DOI、PMID、题目去重。
提示这份记录是在每条检索式最多取回 200 篇的版本上做的。现在向导保存的检索式每次最多取回最新的 2000 篇（Crossref 200 篇），一次向数据库要 200 篇，分几次取完；同样的两条会把命中的 205 篇和 635 篇都带回来，后面的篇数和用时也相应变多。上限在检索式的「每次取回」里改。

一共 355 篇，全部是「待判断」：先宽一些地导入，再逐篇判断。导错了，「导入记录」里那一行的「撤销」会删掉那一批新增的、还没人处理过的文献。页面上方的「自动更新」可以让检索式每 6 小时、每天或每周自己运行，新文献同样以「待判断」进来。

5让助手筛选

列表里已经能看出混进了不相干的东西，比如一篇讲城市绿地里烟头的。355 篇一篇篇看摘要要半天，先交给助手读一遍。

打开左侧的「筛选」，页头是「批量」和「逐篇」两种看法，先用「批量」。「筛选目标」写什么样的文献应当收进这个库；留空则只按主题判断，写清楚边界会准得多：

筛选目标

收录：以植物为研究对象、实际产生或分析了单细胞 / 单核转录组数据（scRNA-seq、snRNA-seq）的原创研究、方法与数据资源，以及该领域的综述。不收录：研究对象不是植物、只用 bulk RNA-seq、或只是顺带提到单细胞技术的文献。

点「让助手判断 355 篇」。助手 8 篇同时读，有全文读全文，这里都只有摘要。进度条下面是正在读的文献，读完的带着建议排进队列。

355 篇这一轮用了约 4 分 40 秒，建议分成四组：

表 2　助手对 355 篇的建议。
建议篇数意思
已纳入257符合筛选目标
相关52和主题有关，但不满足收录条件，留作参考
证据不足4摘要里看不出来（其中 2 篇没有摘要）
不相关42不属于这个主题

中途可以点「停止」，没读的留到下一轮；个别文献没判断成不会打断这一轮。筛选目标随时可以换：已有的建议标为按旧目标，再让助手按当前目标判断一遍，你已经做的判断不会被改动。

6确认收录判断

助手的建议只是建议。它不改任何一篇的收录判断，改的人只有你。一轮读完，进度条下出现「助手读完了，去确认它的建议」，右上角的按钮也变成「确认 N 条建议」，点它进入「确认建议」：

每一行是一篇文献、助手的理由和它将得到的判断，默认都勾选。不同意的点右边另一个判断，拿不准的取消勾选，留在待判断；「把握低的在前」把最该看一眼的排到上面。图 8 里就有一个要改的：那篇背根神经节的研究没有摘要，助手只能说「证据不足」，看题目就知道它不相关。最后点「确认这 N 篇」，勾选的一次写成收录判断，助手的理由一并记为判断理由。写入之前什么都不会改动，写入之后页面上方有「撤销」。

只想先处理一组，在「批量」里点队列上方的分组，例如「不相关 42」，按钮就成了「确认这 42 条「不相关」」。想一篇篇细看，切到页头的「逐篇」：一次一篇，助手的建议、理由和它依据的原句在上（原句逐字引自摘要或全文，引不出原文的理由不会被当作依据），摘要在中间，四个判断在下。按 Y 已纳入、R 相关、U 证据不足、N 不相关，A 采纳建议，判断完自动换下一篇。

那次运行最后写入了 257 篇已纳入和 42 篇不相关，剩下 52 篇相关、4 篇证据不足留着：这些正是值得自己看一眼的。回到「全部文献」，不相关的默认隐藏，列表是 313 篇，「收录」一栏有了结果。

回顾

  • 在「设置 › AI」接上自己的模型服务，并把筛选的并发调到 8。
  • 建库时写了一段具体的主题，助手据此为两个数据库拟了 6 条检索式；按试检索命中的标题选了 2 条，导入 355 篇。
  • 写下筛选目标，助手用约 4 分 40 秒读完 355 篇摘要；你在「确认」里过目后写入，库里留下 313 篇。
  • 接下来：精读其中一篇，见教程 04；就整个库提问并核对出处，见教程 06；用 /review 分阶段写综述，见教程 08。
