Per-module detail moved out of `CLAUDE.md`. Read the section for the module you are about to change; the rules that hold everywhere are in `CLAUDE.md`.

## Author names

Author names are kept as the source wrote them, `A; B; C`, in three forms: `Zhang, Tian-Qi` (PubMed, Crossref, BibTeX), `Tian-Qi Zhang` (arXiv, Zotero) and, in libraries from before, `Zhang TQ` (Europe PMC, the family name first and initials after it). `model::author_names` is the one reader that says which word is the family name, for a whole list at once (a name ending in one capital is the third form, one ending in two or three when most of the list is written so); `Paper::citation`, the citation keys and reference list of `cite`, and the BibTeX of `export` all go through it, and a new reader of names does too. `lookup::europepmc_hit` now stores such names with their comma (`model::family_first`, or the name's own parts when the record has them). A key already cited stays as `cite_keys` has it.

Where in its journal a paper is: `Paper::volume`, `issue` and `pages`, three strings (columns added by `store::add_columns`; an older build leaves them as they are when it saves a paper). Every reader fills them: Crossref (`volume`, `issue`, `page`, else `article-number`), Europe PMC (`journalInfo`, `pageInfo`), PubMed (`JournalIssue`, `Pagination`), BibTeX (`volume`, `number`, `pages`), RIS (`VL`, `IS`, `SP` / `EP`), Zotero (the fields `volume`, `issue`, `pages`), and 按题目补全 offers them like any other field. `model::clean_pages` is the one shape pages are kept in (`357-362`: a plain hyphen, the last page in full); `lookup::merge_lookup` takes a second source's three only when it names the same journal or none. They are written by `csl::entry`, `cite::reference` (through `Paper::placed`, `585(7825), 357–362`) and the BibTeX and CSV of `export`.

## Note saving and export (`notes.rs`)

Note saving/export: core's notes.rs prepares editable Markdown drafts from personal notes and selected conversation questions, copies images for local export, and keeps publication metadata at the existing year precision. Desktop src/notes.rs and the tools list_note_sources / prepare_note / export_note / save_note_to_notion share that document. net's notes.rs publishes through the existing mcp.rs client and OAuth (no separate client/settings DB). Per-library note_saves reserves writes before sending; an OS lock prevents reconciliation during an active write. Uncertain writes stop and require explicit human reconciliation via resolve_note_save. The generic MCP client never replays tools/call after transport errors. Cache saved links in Library::reload, never query the DB from render. Desktop saving uses a compact destination picker with optional read-only preview; source choices only appear for chat, refresh the document automatically, and preserve edited titles. Debug startup exportnote opens personal-note saving; exportnote:paper or exportnote:library selects chat sources; notedestination:local, notepreview and notepick:<index> exercise the dialog without writing. Live test: cargo run -p wisp_net --example note_smoke -- <explicitly approved parent page ID>, with an isolated WISP_STUDY_HOME already authorized for Notion; it creates synthetic content and leaves its page for inspection.

## Word files (`docx.rs`)

`docx.rs` reads and writes Word files for 写作, by hand (a zip reader that keeps unchanged entries as packed, an XML tokenizer that keeps what it does not change as written): a tree parser that writes its tree again would not promise an untouched paragraph back to the byte. `read` gives the body's paragraphs that say something (text of `w:t`, a tab or line break as a space; struck text not counted, inserted text counted; no table of contents, nothing inside tables), each heading's level (its style's name `heading N`, which Word keeps in English, or an outline level) and the comments with the words their ranges cover. `rewrite` takes the paragraphs the manuscript now has (`Wanted`: text, role, comments) and writes the same file saying them: `align` matches old and new paragraphs (equal ones first, then those alike by `likeness`, as many leftovers as came changed in place, the rest taken out and put in), an unchanged paragraph is the original XML, a changed one is changed inside its runs (`Para::edited`: word-level `ops`, what stays keeps its run, what comes joins the run of the text before it; `Options::track` writes `w:ins` / `w:del` with ids after the file's largest), a new one is set like the nearest paragraph of its kind, and one taken out that holds a section break or a picture keeps those. Marks with another half elsewhere (bookmarks, comment ranges, field characters) are never dropped. Comments go into `word/comments.xml` (made with its relationship and content type when the file has none) and their ranges cut the runs they start and end in, but never a revision: a range that starts or ends inside a `w:ins` (another's, or one just written) stands before or after all of it (`place`). A range mark inside `w:ins` is itself read as inserted, and LibreOffice then takes the unchanged words the range covers as inserted too, so rejecting the change would delete them. The tests build small files; real ones are tried with the `docx` example and LibreOffice.

## 批注 and manuscripts from files (`comment.rs`, `manuscript.rs`)

A paragraph to be written can also carry what a reader of the file needs of a citation (`Wanted::anchor`, `links`, `looks`), put on after the text is settled (`dressed`): a look cuts the runs it starts and ends in and sets `w:i`, `w:b`, `w:vertAlign`… in the order the format wants them (`with_look`); a link is a complex field, `HYPERLINK \\l "<bookmark>"`, whose marks stand around the paragraph's own runs (inside an insertion when its words are one: `place` with `through`) and so are a 域 a click follows; the paragraph a link leads to is bookmarked under a hidden name (`_WPREF_n`, numbered after any the file has; the bookmarks take the `w:id`s before the revisions). A link whose anchor no paragraph has is left out. For a file cited anew (`restyle.rs`): `marks` gives the body's fields (code, and where the words they show begin and end; one inside another after it) and the raised words of each paragraph (`w:vertAlign`, or lifted by `w:position` as LibreOffice writes it); `unfielded` takes fields out whole, marks, codes and the fields inside them, leaving their words; `Wanted::edits` are a paragraph's changes as the caller knows them, made instead of the word diff when they do give the new text (the diff takes `grow1.` for one word); `Wanted::fresh` is a paragraph never taken for one of the file's changed, so a new reference entry keeps none of the old one's italics; `Wanted::level` takes what raised some words off them.

## Citation styles (`csl.rs`, `cite::Formatter`)

`cite::Style` is how a manuscript exported to Word cites: the two simple forms made here (`AuthorYear`, `Numeric`) or a CSL style (`Csl`), the definition files Zotero uses, processed by `hayagriva` (its `archive` feature carries some ninety styles and every locale). A style's key is what `Settings::cite_style` keeps: `author-year`, `numeric`, `csl:<name>` (built in), `file:<file>` (added to `styles/` in the data root, `csl::add` / `save`; a file replaced is kept in `styles/removed/`), `zotero:<file>` (in `~/Zotero/styles`, read where it is; listed only when neither built in nor added, by the style's `<id>`). `csl::style` reads the key; a dependent style is its parent when that is built in or beside it, a style that cites in footnotes is refused. `csl::render` gives every citation group and the list as `cite::Rich`: the text, its looks, and which words cite which paper (the processor marks each item of a citation, `ElemMeta::Entry`), with the locale of the manuscript's language. A paper is an article in its journal with authors, year, DOI and PMID (`csl::entry`); volume and issue go on the journal (the parent `Periodical`), the page range on the article, each as a number or range where it reads as one (`MaybeTyped`) so a style can shorten a range or give it an en dash, else as written (`S1`, `e1234`). `Formatter::rich` writes a text's groups (`apply` is its words alone) and `references` is the list with each entry's paper, so `manuscript::wanted` (given `Cites`) makes every citation a link to the entry's anchor; only groups whose every key names a paper count for numbers and entries. A CSL group cited again reads as it did the first time. Works that are no papers are cited from CSL-JSON (`csl::Record`, hayagriva's `csl-json` feature; `record_of` makes one of a paper): `render_records` takes groups of `Cite` (record id, a page, `narrative` for authors the sentence already names, written from the year on in a style whose citation says the year and whole in a numbered one) and the works to list uncited; a field of a record the processor cannot read is left out, not the record. The tools `list_cite_styles`, `read_cite_style` (a built-in one written out as XML), `try_cite_style` (a style or a CSL text tried on the library's papers, kept nowhere) and `save_cite_style` (in `WRITING`, not asked about: it adds a file the person then chooses in the export menu) are how the assistant makes a style to the person's wishes.

## A Word file cited anew (`restyle.rs`)

`restyle.rs` restyles the citations of a Word file that was written elsewhere and is no manuscript of the app. `inspect` reads what it cites, in this order of trust. Fields of Zotero's (`ADDIN ZOTERO_ITEM CSL_CITATION {…}`, Mendeley's `ADDIN CSL_CITATION` too) carry every work as CSL-JSON (`itemData`), so nothing is guessed; a field with a prefix or suffix, one edited by hand in Zotero (`dontUpdate`), an author-only one or one with a locator that is no page is left whole and said (`Found::problem`). Without such fields the file is read as text (EndNote's `ADDIN EN.CITE` and Word's own `CITATION` are recognised and said to be what they are; their data is not read): the list is the paragraphs of a list field (`EN.REFLIST`, `BIBLIOGRAPHY`) or those after the last heading `headings::opens_references` knows, up to the next heading; each paragraph is an entry, numbered by its label (`label`: `[3]`, `3.`, `（3）`) or its place. The body's citations are found by number (`numbered`: square brackets, and raised numbers, which are not a unit's power) and by author and year (`author_year`: `(Zhang et al., 2024a; Li & Wang, 2019, p. 5)`, `Zhang et al. (2024)`, `（张三等，2020）`, matched to the entry of that year whose first author is so named, the letter and the second author telling two apart); the file cites the way more of them are found. An entry becomes a record (`resolve`): the library's paper (DOI, PMID, or its title standing in the entry's text; the entry's own volume, issue and pages where the record has none), a Crossref lookup of its DOI, its own text read by rule (`parse_entry`: GB/T 7714 with its `[J]`, author-date, and year-last forms; a guess, said so), a Crossref search by its words (kept only when the record's title stands in the entry), or one the caller gives (`given`: the assistant reads a reference better than rules do). The network is a `sources::Fetch`, asked only when given. An entry that could not be read (`UNRESOLVED`) stays as written at the list's end, and so do the citations that name it; nothing is dropped or made up. `Inspected::report` is what the tools hand back. `restyle` renders with `csl::render_records` (entries nothing cites are kept in the list, after the others) and writes with `docx::rewrite`: each citation an exact edit of its paragraph (`Wanted::edits`) with links to the entries' anchors, the old list's paragraphs replaced by new ones written afresh (`Wanted::fresh`), the fields of rewritten citations and of the list first made plain text (`docx::unfielded`), so no field of Zotero's is left half rewritten. A raised number that becomes words is set on the line with a space before it (`Wanted::level`), words that become a raised number lose the space. A style that writes no list leaves the old one. Tools: `read_docx_citations` (read-only) and `restyle_docx` (in `WRITING` and `CONFIRMING`; `output` never an existing file, by default beside the source as `-restyled`), both with `lookup` and `entries`.

`comment.rs` is 批注: `manuscript_comments` (made beside the library's tables, no version bump), each about a quotation of its section and found again by what it says (`locate`: as written, else by its characters without spaces and quote styles), from a Word file (`FILE`: never removed, only marked `DONE`), the person, or the assistant. `review_prompt` / `parse_review` are the assistant's review of a section: a JSON list of `{quote, comment, replacement}`, each quotation checked against the text (kept only when found within one paragraph and not overlapping an earlier one). A proposal is taken only by the person (`Comment::taken`: the comment moves to the new words and keeps the old; `taken_back`). `manuscript.rs` has the rest: `from_word` / `from_markdown` make a `Draft` (sections at the highest heading level; a Word file without heading styles has its headings guessed by `headings::guess` (a name every paper has, numbering `一、` / `（一）` / `1.1`, a figure at the end `（图1）`, bold, a short line between running text; numbered items next to each other are a list, nothing after 参考文献), listed in `Draft::headings`, and is cut only at those the person ticks in `Modal::Headings` (`from_word_with`); a Markdown file without headings at `structure::canonical` names; a title; `bare` for text under no heading), `Store::split_section` / `merge_section` are 设为标题 / 从这里拆成新节 under the editor and 并入上一节 in a section's menu: a heading made of a paragraph is written back as that paragraph, a section cut off without one is `bare` and its name goes into no file. `Store::manuscript_blank` says whether a manuscript is still the empty one 写作 opens a library with (no title, the IMRaD sections without a word, no snapshot, comment, conversation or source file), and `Store::retire_blank_manuscripts` puts such ones away when a real one is made or taken in, so no stray 未命名稿件 stays beside it. `Store::import_manuscript` keeps it with the Word file itself under `manuscripts/` and a `manuscript_sources` row, `wanted` lays the manuscript out as the file's paragraphs with the comments on them, and `Store::manuscript_word` is the export (the source file written again, or `docx()` with comments for a manuscript that has none). `read_manuscript` lists a section's open comments.

## 配引用 (`citefind.rs`)

`citefind.rs` is 配引用: the papers of the library a text can cite, sentence by sentence, and nothing that writes a word of the manuscript's. `sentences` cuts a text and keeps where each sentence stands (full stops of either script, semicolons, line breaks; not after an abbreviation, inside a number or inside brackets); `plan_prompt` / `parse_plan` are what a model says of each sentence before the search: what it does (`INTENTS`: background, a finding of someone else's, a method, an open question, a comparison, the authors' own words) and the search words for it in the library's language (`library_language`; `words_prompt` / `parse_words` are the words alone, which 出处 uses); `search` ranks the papers for every sentence, each query twice (by the record, and by the paper's best sentence among the abstract's and the stored full text's, over `retrieval::index_for`), merges the rankings and names the sentence that matches best, keeping a paper only when record and sentence hold a fair share of a query's words. What a sentence can cite goes by what it does: for a finding, a comparison or a method a sentence outside the paper's introduction is named when one fits, background puts the reviews first (`reviews`: a full text without methods or results, or a record that says so), the authors' own words are not searched for. `named` reads the works a paper's sentence names by author and year (`(Tang et al., 2009)`; numbered citations name nothing, the reader leaves raised numbers out) and `holds` finds the library's paper for one. `judge_prompt` / `parse_judgement` are a model's choice among the papers found, by a standard per intent (a JSON list of sentence, `cite` with key, role `SOURCE` or `REVIEW` and why, and `restates`: papers that only tell what others found, which are no citation but a lead to the works they name; it chooses, it never names a paper of its own); `place` / `placed` write `[@A; @B]` before the mark a sentence ends with, into a citation already there, never a key twice. The tool `find_citations` (text, optional `queries` and `intents` per sentence, `perSentence`) is `sentences` plus `search`, each candidate with `review` and the `names` of its sentence.

## 出处 (`passage.rs`)

`passage.rs` is 出处: the sentence of a paper that a citation of the manuscript rests on, so a reference leads to where it is from and not only to the paper. `cite_passages` (made beside the library's tables, no version bump) keeps one per manuscript, paper and citing sentence (`claim`: the sentence without its citations, `passage::claim`), with the paper's sentence, its part and page, why, and where it is from (`CITED`: the person cited from that sentence; `MODEL`: looked for afterwards and chosen by a model; `WORDS`: found by words alone, unchecked). Nothing is written into the manuscript, whose text stays `[@Key]`: `citations` gives every citation its sentence and `assign` finds its passage again by how alike the claims are (`docx::likeness`), so it stays with the sentence while the text is written on; a sentence written anew or translated takes the paper's unclaimed passage of that section, said to be `loose`. Looking afterwards: `sentences_of` is what a paper says of its own (the abstract's sentences, then the stored full text's), `nearest` ranks them against the sentence and any search words (BM25, merged; `fair` when one holds a fair share of the words), `choose_prompt` / `parse_choice` are a model's choice among them, which may be none: then a row without a passage is kept (`Passage::found`), said under the reference as a citation its paper does not bear out, and not asked again. The tool `find_passages` (paperId, `texts`, optional `queries`) is `sentences_of` plus `nearest`; `read_manuscript` lists each section's passages. `Store::merge_section` / `split_section` take the passages along, and `cite::convert_ai_citations` hands back the sentences an answer quoted (`Quoted`) for `passage::quoted`.

## 改稿 (`revise.rs`)

`revise.rs` is 改稿, the engine of the box under the manuscript where the assistant is told what to change in a section. The model answers with SEARCH/REPLACE blocks (`<<<<<<< SEARCH`, the words to find, `=======`, the words to put there, `>>>>>>> REPLACE`; no words to find is the end of the section, no new words a deletion), so a change can be made the moment its block is complete. `read` reads a reply as far as it has come (the complete blocks, the one being written once its words to find are in, what is said beside them; words begun on the opening marker's line and a block not closed are read too, as smaller models write them), `find` / `place` say where a change goes in the text as it now stands (as written, nearest to the last change, else by `comment::locate`; a paragraph taken out takes its empty line along), `follow` keeps a place while one stretch of the text changes around it, `added` is the new words to light up (`ai::word_diff`), `prompt` what the model is told. No store, no tool: the window makes the changes.

## 助手写 (`compose.rs`)

`compose.rs` is 助手写, the writing page's other mode, in which the assistant leads: the person talks with it and it writes the manuscript with two tools of its own. `edit` is the tool `edit_section`: one section written or changed, by `edits` (each made where its words stand, `revise::place`; no words to find is the section's end) or by `text` (the section's whole new text); citations are `[@Key]`, or `[@<paper id>]` which `keyed` turns into the key, and the keys cited are kept with their papers; the section's text is kept as a snapshot (`assistant`) first, and what was not found is handed back as `missed`. `outline` is the tool `set_outline`: the sections a manuscript is to have, in order, with its title and language when given; a section named by id or present name stays what it is, the others are made (`Store::arrange_sections`, one transaction), and one left out goes only when nothing was ever written in it (no text, no snapshot): one with text stays, after the others, and is said (`kept`). `call` is what a conversation's tool call goes through instead of `tools::call_in`: for `edit_section` the citations of the words to be written are the conversation's (`label_citations`: `[P3 p.5 "…"]` to `[@Key, p. 5]`), the sentences they quote are kept as passages where the paper says them (`keep_quoted`, origin `CITED`), and the result names the quotations no paper holds and the labels that name no paper, for the model to put right. `note` is what every question of such a conversation tells the model: the manuscript's id, language and outline with lengths, the section on show, what is selected, and how to work (read before changing, find the sentence before citing, nothing of the manuscript's text in the conversation). `hunks` is what changed between two texts line by line, which the window lights. No table and no version bump: the conversation is an ordinary one, kept under the manuscript's id.

## 图片库 (`figure.rs`)

`annotation.rs` is the marks on a PDF, kept apart from the file in `pdf_annotations`: an underline or a highlight of one page, the text it covers, a box per line in the page's points, a note, and for a highlight its colour (a key of `COLORS`, the `color` column added by `add_columns`; empty for an underline, and a highlight from before colours reads as the first). The range of a mark never changes; its note (`update_pdf_annotation_note`) and a highlight's colour (`recolor_pdf_annotation`) do. Tool: `list_pdf_annotations` (read-only).

`figure.rs` is 图片库: pieces cut out of PDF pages and kept as pictures under `figures/` in the library folder, one `figures` row each (number, legend, notes, tags of their own, and the paper, file, page and box they came from). The table is made beside the library's own like the manuscripts'; no version bump. `caption` finds the caption a piece belongs to among the page's lines (`pdftext::lines`): a line that `opening` takes for a caption's start (`Fig. 2 |`, `Figure 3.`, `Table S1`, `Extended Data Fig. 4`, `图 3`; not running text that begins `Figure 2 shows` or `Fig. 2a). These`), the nearest within `REACH` that shares the piece's columns (a figure's under it, a table's over it), read on through the lines set alike under it. `Ask`, `ask_prompt` and `read_legend` / `read_tags` / `read_notes` are what a model that sees the picture is asked and how its answer is read. A figure is listed while its paper is outside the trash; `delete_paper` and `remove_figure` set the picture aside in `removed/`. A picture a model drew is a figure without a paper (`paper_id` empty, `Figure::drawn`): so `paper_id` is no reference to `papers`, a trigger takes a deleted paper's figures along instead, and `figure::migrate` makes over the table of a library from before (same columns, so an older build reads it as before). Tool: `list_figures` (read-only).

## Screening (`screening.rs`)

Screening is against the library's goal (`LibraryInfo::criteria`, 筛选目标; empty means by the topic), saved as it is typed. Each suggestion keeps the goal it was made against (`screening_suggestions.criteria`, NULL for one from before, which counts as current; `Suggestion::made_for`); one made for another goal is shown as 按旧目标 and asked again by the next run. Each bulk run of the assistant (not `Cmd::ScreenAskOne`) calls `Store::begin_round(criteria, scope)`: a row of `screening_rounds` (made beside the library's tables, no version bump) with the goal, the scope (`pending`, `included` for 继续筛, `decided` for 复核) and the tally by status of the papers outside the trash, unless the latest row has the same goal (the same round going on). `screening::funnel(rounds, now)` makes the stages: `entered` by scope from the round's own counts, `included` the next round's included count (the last round's: `now`), so trashing or deleting papers later changes no finished round. Imports after a round began and rounds screened wholly by hand are not counted. 复核 (`Cmd::ScreenRecheck(false)`; with `true`, only the included papers) asks about the decided papers too: one the assistant now sees otherwise comes back to the queue (`Library::rechecking`, until the person decides it again, which keeps or changes the decision), the decision itself is never touched. Columns added later go through `store::add_columns`.

A suggestion never writes `papers.screening_status`: only the window does (确认 takes the decided papers back in the queue as well, `Library::confirmable`, so a round of 继续筛 is confirmed in one go; `Before` keeps what they were for 撤销), in `Cmd::ScreenDecide`, `Cmd::ConfirmApply` (the ticked suggestions written together, `Store::set_screenings`: one transaction, all or none) and the detail panel. An excerpt is kept only when `ai::locate_quote` finds it in the abstract or the full text.

The person's side of screening is `screening.rs`: `DECISIONS` and `status_of` (the keys: Y / R / U / N or 1 to 4, P or 0 for waiting again), `reason_for` (the reason kept with a decision: the assistant's when the person agrees, their own when the decision stays, none otherwise), `Round` (逐篇: the papers fixed when the round starts, the one on show, the decisions made so that the last can be taken back with what the paper was, `Before`) and `Confirming` (确认: the status chosen where it is not the suggested one, the papers left out, `plan` is what gets written; a suggestion made with nothing of the paper to read, `screening::unread`, `basis` `none`, is not ticked until the person ticks it or chooses a status, as the extract run does not ask about such a paper at all).

## A library in one file (`archive.rs`)

`.wispstudy` is a gzipped tar, written and read in `archive.rs` itself (ustar headers; a PAX record for a path over 100 bytes or not ASCII, or a file over 8 GiB; GNU long names read too), streamed both ways so a library of PDFs is never held in memory. The first entry is `wispstudy.json` (`Manifest`: `format`, which `FORMAT` bumps when an older build would misread an archive, and what is inside), so `peek` reads only the head; the rest is the folder under `library/`. The database goes as a `VACUUM INTO` snapshot, which is consistent while the app keeps it open; without attachments, `papers/` stays behind and the snapshot's `resources` rows are deleted, taking their text, sentences, structures, origins and PDF annotations with them (`ON DELETE CASCADE`). `removed/`, the journal files and downloads in progress never go. The export is written to `<name>.part` and renamed. `import` unpacks into a hidden `.importing-<id>` folder under the data root, skips any path that is not inside (`inside`) and the `._` forks a Mac's tar adds, opens the database once (a newer schema is refused, an older one brought up to date), writes `library.json` with a new id and a free name (`(2)`, `(3)`…) and only then renames the folder into place; on failure the hidden folder is removed. The tools are `export_library` (refuses to overwrite) and `import_library` (with `create_library`, not in `library_catalog`).

## The trash (`store.rs`)

A trashed paper is only marked (`trashed_papers`). Leaving the trash is for good, one paper (彻底删除, `purge_trashed`, which refuses a paper that is not in the trash) or all of them (清空回收站, `empty_trash`); both end in `purge`: the rows go in one transaction (`delete_rows`: the paper's row with what refers to it, and its conversations), then the files and pictures are unlinked from disk, each only when it lies inside the library folder and no remaining `resources` or `figures` row names it. `delete_paper` takes the same rows and moves the files to `removed/` (`set_aside`); it is what an undone import uses, never the trash. A file that cannot be unlinked is left and does not fail the call.

## 提取 (`extract.rs`)

提取 (`extract.rs`): a model's proposals for the custom fields. `FieldDef::hint` (a column added by `add_columns`) is what a field is said to be for, which the model is told; `extract::SUMMARY` (要点) is an ordinary Text field the window offers to add. `extract::prompt` asks about several fields of one paper in one request (the paper as `ai::paper_to_read` gives it, shared with screening) and `parse` reads the reply by field number or name; `coerce` brings an answer into the field's shape (a Select answer becomes one of its options or stays as said, which `fits` then refuses: a new option is never written) and the excerpt is kept only when `ai::locate_quote` finds it. One proposal per paper and field is kept in `field_proposals` (made beside the library's own tables, no version bump) with the definition it was asked under (`asked_as`); where it stands is read off the paper, not stored (`standing`: open, held by the field, silent, dismissed, stale), so a written value keeps the sentence behind it and taking a writing back makes its proposals wait again. `wanted` is which fields a run asks about for a paper (empty ones not asked about under the present definition; again when only the abstract was read and the full text is stored now). The person's side is `Reviewing` (ticked by rule: a value the field can hold, for an empty field, with a sentence behind it) and `taken` (a multi-value field keeps what it has). Only `Store::set_fields` writes `paper_fields` for this, one transaction, all or none; the tool `suggest_field` (in `WRITING`, not `CONFIRMING`) saves a proposal and refuses a Select value that is not an option.

## Models, providers and proxies (`provider.rs`, `imagegen.rs`, `judge.rs`)

Models per task: `Settings::providers` holds any number of model services (`provider::Provider`: address, key, proxy, protocol, and the `Preset` it started from), each offering any number of `provider::Model`s with an `id` (given by `Settings::tidy` / `add_provider` / `add_model`, unique across providers, never reused while in use) and its own `effort` (`ai::EFFORTS`: empty sends nothing, `off`, or a level). A new settings file starts with DeepSeek, Kimi and GLM (`provider::DEFAULT_PRESETS`); each preset has its own key variable (`DEEPSEEK_API_KEY` …), so one service's key never goes to another. What a request is made with is still the flat `ai::Profile` (`Provider::profile`, `Settings::profile` / `profiles`). `Settings::tasks` binds `Task::Chat`, `Screen`, `Translate` and `Structure` (写作's groundwork) to a model id; `Settings::profile_for` falls back to the chat model, then the first that can answer, then the first. A file from before providers keeps `profiles`, which `Settings::load` turns into providers (`migrate`: profiles with one address, key and proxy become one provider, their ids kept) and never writes again. `ai::apply_effort` is the one place that knows how each protocol, model and service spells thinking; a new service's way of turning it off goes there.

生图 (`imagegen.rs`): a provider's model either answers in words or draws (`provider::Model::kind`, `imagegen::KIND`; `Model::draws`). A name that says so makes a model added a drawing one (`imagegen::looks_like`, in `Settings::add_model`), the model's menu on 设置 › AI › 模型 changes it (`Settings::set_model_kind`), and presets bring theirs (`Preset::images`: OpenAI's gpt-image, the `gemini` preset, `ark` for 火山方舟's Seedream). `Task::Image` is bound only to a drawing model and the other tasks never to one (`Settings::tidy`); `Settings::profiles` lists the models that answer in words, `image_profiles` those that draw, and `profile_for(Task::Image)` is `None` while no model draws: it borrows nothing (`Task::WORDS` are the other four). A drawing model is asked through one of three interfaces (`imagegen::Interface`, chosen in `Model::interface` or guessed by `imagegen::guess`): OpenAI's Images API (`{base}/images/generations`, also Seedream and most relays), Gemini's own `generateContent` (at Google's address; from a base ending in `/openai` or `/v1` the root is worked out), or chat completions that answer with a picture (a Gemini model behind a relay). `imagegen::request` builds the request (sizes and parameters per model family go there), `imagegen::read` finds the picture in the answer (bytes, or an address to fetch), `wisp_net::generate_image` sends it and returns a PNG, JPEG or WebP. A new service's way of asking for a picture is an arm in those two functions.

判断 (`judge.rs`): the third kind of model (`judge::KIND`, `Model::judges`; `Model::speaks` is one that answers in words), after TypeSafe's System One models (Jev): given a state and questions whose answers are fixed beforehand, it answers each with one of them and a probability for every one, and writes nothing. The `typesafe` preset brings `jev-latest` (`Preset::judges`), a name beginning `jev` makes a model added one (`judge::looks_like`), and the model's menu says its kind (`Cmd::SetModelKind`, `Settings::set_model_kind`). `Task::takes` is the one place that says which kind of model does which task: only `Task::Screen` takes a judging model, and only when the person chose it (`profile_for` never falls back to one); 提取, which shares screening's model, asks `Settings::speaking_profile_for`. In a screening run (`screen_next`) such a model is asked with `judge::screen_request` (one `choice` question, include / related / irrelevant, about the record and abstract, or the first pages without one; `POST {base}/systemone`) through `wisp_net::judge`, and `judge::read_screening` makes the `Judgement`: the verdict with the highest probability, 证据不足 when its confidence is under `SURE_ENOUGH`, the probabilities as the reason, no excerpt. Errors come as `detail` (`ai::error_message`). A new use of such a model is a question built with `judge::request` and a reader for its answer.

Proxies: `Settings::proxy` is global and applied with `wisp_net::set_proxy` (app start, 设置 › 网络, and `wisp`); `Profile::proxy` overrides it for one model service (`direct` = none) and travels in `HttpRequest::proxy`. Empty everywhere means ureq reads the environment. `settings::proxy_problem` is the address check.

## Translation

Translation: `ai::translate_request` (instructions from `Settings::translation_prompt`, else `ai::TRANSLATION_PROMPT`), kept in the library's `translations` table under `store::translation_key` (text and instructions), so a text is requested once. The window translates the selected paper's title and abstract while `Library::show_translation` is on.

Batch translation: the marked papers' menu has separate title and abstract actions. `translation::Batch` snapshots and groups the selected texts, counts progress in papers, and skips empty fields; `src/translate.rs` shares cache and in-flight requests with the detail panel and keeps `Settings::translate_workers` batch requests in flight (`Batch::take` / `working`, answers settle in any order; 设置 › AI › 任务, default 4). Stop sends nothing more and keeps the answers already asked for; retry reuses successes. A per-open-library `Arc` rejects late answers after closing/reopening. Debug steps `key:ctrl-a,translate:titles` / `translate:abstracts` exercise the marked selection; `translate:stop` stops it.

## Organising and the manuscript tools (`organise.rs`)

Organising (`organise.rs`, tool `organise_papers`): tags added or removed, the star, the reading status and a paragraph added to the notes (marked as the assistant's, never replacing what is there), for any number of papers in one call, written in one transaction (`Store::organise`) or not at all. `organise::apply` changes a paper in memory and says in words what it changed, and nothing where the paper already is as asked; `Store::organise_plan` is the same without writing, which `organise::preview` (`tools::preview_call`) turns into a line per paper for the consent card (`PreparedCall::details`). A call that could not run (a paper not there or in the trash) is not asked about: it fails by itself. `ai::resolve_labels` reads labels in a list of objects too, so `changes[].id` may be `P3`. A new thing an agent may change about held papers goes there; screening and the custom fields stay with their proposing tools.

The manuscripts are read by `list_manuscripts` and `read_manuscript` and written by `edit_section` and `set_outline` (`tools::MANUSCRIPT`, see `compose.rs`). Those two are in `CONFIRMING`: the window's assistant asks before each (`compose::preview` is the card's lines), except in the conversation that writes that very manuscript (写作's 助手写), where the pen was handed over. An answer also goes into a manuscript by the person's hand: 插入到稿件 under an answer of the library's conversation (`MenuKind::InsertInto`, the sections of the manuscript on the writing page; `Workspace::insert_into_section`) adds it, or what is selected in it, at the end of a section with `Store::append_to_section`, which keeps the section's text as a snapshot first and the citation keys with their papers; `cite::convert_ai_citations` makes the citations the manuscript's.

## Conversations

Conversations are kept per library, under what they are about (`conversations.paper_id`: empty for the library's, a paper's id, or a manuscript's id for the conversation that writes it; `Library::talk_about`): `conversations` holds an `ai::Transcript` (what was said, and the sources its answers cite) as JSON, `conversation_images` the pictures. What the model read is not kept: a conversation reopened from the history builds its context anew, and `ai::build_context` takes the transcript's sources as `known` so the labels in old answers still name the same papers.

## Full text, structure and languages (`pdftext.rs`, `structure.rs`)

Full text for writing (`pdftext.rs`, `structure.rs`): `fulltext::file_pages` reads a PDF with hayro's interpreter first (`pdftext::pages`: glyphs with position, size and weight become lines, and a blank line marks every break the page shows, so a heading stands alone; raised citation numbers are left out, ligatures spelled out) and falls back to pdf-extract, which panics on about a third of publisher PDFs. `structure::blocks` turns the page text into paragraphs and headings, `assign_sure` gives each paragraph its part by rule (a heading that names a part, `canonical`; without an "Introduction" the text before the paper's first own heading is the introduction; a review's own headings are `other`; an "Abstract" heading lasts `ABSTRACT_WIDTH` or until a heading of the paper's own, then the part it interrupted goes on) and says where it only guessed, `sentences` cuts the kept paragraphs. The words of a button the publisher draws on the page (Crossmark's "Check for updates", `is_button`) are passed over: standing alone they looked like a title and headed the sentences after them. `parse_outline` reads a model's answer about the outline; one that names no block because the file has no body text (`none`, or nothing at all, which is what "list only body text, explain nothing" comes to for a supplement) is `structure::NO_BODY`, said as it is and not counted towards the run giving up (`wisp_net::NO_CONTENT` is how the window tells that empty answer from a failure). A hyphen at a line's end is kept or dropped by the paper's own spelling (`Lexicon::keeps_hyphen`: the compound written elsewhere, the word written whole elsewhere, a gene or a number before it, a closed prefix, and in English two words the paper writes on their own); test a change on real lines both ways. `Store::save_fulltext_pages` does this for every text it keeps: `sentences` rows plus one `structures` row per file (`rules`, `model`, or `none` for a file without text; `open` counts the guessed paragraphs, `paragraphs` all of them, and `StructureInfo::worth_asking` / `structure::worth_asking` is the one place that decides whether a model's look is offered: many guessed, or a good share of a short piece).

Languages: lengths are counted in `structure::width` (a Chinese, Japanese or Korean letter counts three), sentences end at `。！？．` as well, a sentence or heading may open with a letter of a script without capitals, `canonical` knows the headings of Chinese, Japanese, Korean, German, French, Spanish, Portuguese and Italian papers, and `words` gives character pairs for CJK runs (Latin words keep the stemmer; `OTHER_STOP_WORDS` beside the English ones). Each text's language (`structure::language`, from the script and the commonest words of its kept body text, `body_language`) is the `structures.language` column, `StructureInfo::language`, and `Sentence::language` on every sentence `section_sentences` returns: that is the field to read when choosing sentences by language. The writing page's groundwork line counts the texts per language when there is more than one. In `pdftext`, a page's usual line spacing (`usual_leading`) keeps Chinese set with wide leading in paragraphs, and a numbered title set like the text (`numbered_title`) stands alone. A file without a `structures` row has not been through it: `tools::extract_missing` and `Workspace::extract_missing` read such files again, so libraries from before 写作 catch up on their own; bump `structure::VERSION` when the rules change and `restructure_outdated` redoes the rule-made ones. The abstract is never taken from the PDF: `find_sentences` reads it off the record.

## Candidate sentences (`retrieval.rs`)

Candidates: the tool `find_sentences` (part; `query` and/or `queries`; optional paper, `tag`, `starred`; `context` adds the sentence before and after from the same paper and part) ranks the sentences of one part (`retrieval.rs`): each query on its own with BM25 over `structure::words`, against a `retrieval::Index` that `index_for` keeps in memory by a hash of the part's texts (no stored word bags, so a change to `words` needs no migration), the lists merged by reciprocal rank fusion (`fuse`, then at most `PER_PAPER` per paper); without a query it returns how each paper opens the part. `tools::extract_missing` first asks `Store::structure_wanted` and returns at once when every file is sorted. The window and `/write` both go through it; `cargo run --release -p wisp_core --example retrieval_bench` times a search over 4000 made-up sentences.

## Open full texts and completing by title (`openaccess.rs`, `complete.rs`)

Open full texts (`openaccess.rs`, tool `find_pdf`): candidates for a paper come from its arXiv number, from OpenAlex and Europe PMC (asked by DOI or PMID, no key and no address of the asker), and, only when one of the two says the paper is open access, from the publisher's own address for the few publishers that hand a PDF to a plain client (`publisher_candidate`). Nothing logs in or goes round a wall; Europe PMC's own PDF rendering is left out because it answers browsers only. What comes back is kept only if it is a PDF (`is_pdf`) and not a paper's supplement (`openaccess::supplement`: every one of its first pages that says anything holds the caption of a supplementary figure or table or opens with a supplement's heading; a repository lists the supplement among a paper's files and an index hands it on as the PDF), with its origin in `file_origins`. The text is read before the file is stored (`fulltext::pdf_pages`), a supplement is said among the reasons and the next candidate is tried. Several reasons are one sentence through `sources::reasons` (each without its own full stop, so no 「HTTP 403。；」). The tools take a second function for this, `sources::Download`, beside `Fetch`. In the window it is a run like the import's (`Library::fetching`, `fetch_start` / `fetch_next`).

Completing by title (`complete.rs`, tool `find_metadata`, 按题目补全 in the detail panel for a paper with neither DOI nor PMID): `complete::find` asks Crossref, Europe PMC and arXiv for records by title (`PER_SOURCE` each), reports each source on its own (`Asked`: found, nothing, or why it failed), makes records of one DOI one `Candidate` and orders them by `similarity` (words in the same order; 1 only for the same title). The title asked for is the paper's, or, while that is the name of its file (`placeholder_title`), the one its first page shows (`pdftext::title_guess`), for the person to correct. Nothing is written by the tool or by a model: the window (`Modal::Complete`, `complete_find` / `complete_apply`) has the person pick a record and its fields; `complete::suggested` is what is ticked beforehand (blank fields, a title that is a file name) and only for a record at least `ALIKE_ENOUGH` like the title; a record the library holds as another paper is refused. There is no browser bridge and none is wanted: sources are asked over HTTP like every other lookup.

## Quotations

Quotations are checked: `ai::check_quote` looks a quotation up in the stored page text (`Quoted`: found, elsewhere, only its beginning, missing, no text), `Library::check_quotes` does it for the finished answers of a conversation, the chips say the result. `ai::citation_spans` is where an answer cites, for the clickable citations in the text.

## Search sources (`sources.rs`)

`sources.rs` searches PubMed, Europe PMC, Crossref and arXiv (PubMed and arXiv answer in XML, read by the small `elements` helper). A search asks for `PAGE` (200) records at a time and again for the next page, until it has what was asked for (`MAX_RESULTS`, 2000, at most) or the database has no more: PubMed gives all ids in one `esearch` and the records by `efetch` a page of ids at a time, Europe PMC pages by `cursorMark`, Crossref by `offset`, arXiv by `start` (`wisp_net::get_text` waits three seconds between two requests to arXiv). A page that fails after others came ends the search with those (`Found::stopped`): `run_search` imports them, keeps the reason in the batch's `error` beside its counts and returns it as `stopped`, and the search is due again within the hour like one that failed. A run after the first does not fetch it all again (`search_new` with `Known`, which `run_search` fills from the store). PubMed's ids come before its records, so a record whose PMID the library holds is never fetched (`Found::passed`, counted as retrieved and skipped). The others send whole pages: when the search's last run went through all it was asked for (`ImportBatch::depth`, the limit it had; 0 for a run that stopped short, and for all of a search's runs once one of its batches is undone) with the same query and no fewer records asked for, a page with nothing new ends the walk, unless the database's count has grown since by more records than were found, which means a new one stands further down (Crossref sorts by relevance, PubMed and Europe PMC by publication date, not by when a record came in) and is looked for through the whole depth. The guide saves its searches with `broad_limit`: the most for the databases sorted by date, one page for Crossref. A saved search is a `searches` row; each run is an `import_batches` row with its papers in `batch_papers`, which is what `undo_batch` takes back: untouched papers only (a decision, reading, star, notes, tags, fields, a file, a conversation about it, a citation in a manuscript or a place in the trash make a paper touched). They leave the library and not for its trash, where they would keep blocking the next run; their records are first set aside as `removed/undone-import-<batch>.bib` (`Undone::set_aside`), which imports like any reference file, so nothing is lost by an undo.
