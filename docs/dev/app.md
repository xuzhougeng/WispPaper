# Window notes (root crate `wisp_paper`)

Per-feature detail of the GPUI app moved out of `CLAUDE.md`. Read the section for the feature you are about to change; the patterns every feature follows (`Cmd`, `Workspace::change`, background tasks, theme, shortcuts) are in `CLAUDE.md`.

## Conversations and the assistant (`chat.rs`)

A library question's scope is the currently shown list (`lib.shown`), so view, search and filters change what the model reads up front. The context is built once with the first question of a conversation. The panel behind 文献 in the conversation's header (`render_materials` in `chat.rs`, `Chat::materials_open`) floats over the conversation and pushes nothing down; a press beside it or Esc puts it away. Before the first question its search box (`Library::scope_find`, the words in `scope_words`, the papers holding them in `scope_hits`, made anew by `scope_refilter` with the words and with every `refilter`: a frame does not search abstracts) narrows the list and the scope with it (`Library::scope_listed`). A row dragged into the conversation (GPUI's `on_drag` with a `chat::PaperDrag`, dropped anywhere under the header; `Workspace::pinning` while it is held) or its plus keeps the question to that paper: it joins `Library::asked`, the same list 就这 N 篇提问 fills, shown as chips over the question box that let each go again (`Cmd::Scope(ScopeDo)`). `Library::scope_papers` is the one place that says what the scope is (`ask` reads the same fields); a new conversation empties both (`scope_reset`), and once the material is built the panel lists what was handed over and nothing can be picked. `Workspace::save_chat` keeps the conversation in the library after the question and after the answer; 历史 lists them (`Chat::history`) and `open_chat` takes one up again.

A library has three conversations, told apart by `Talk`: `Library` (助手, `library_chat`), `Paper` (the selected paper's, `paper_chat`) and `Write` (the one that writes the manuscript, `write_chat`). Every function and command of the chat takes a `Talk`; `chat_of!(lib, talk)` borrows the one meant alone, so the rest of the library can be read meanwhile. What only the library's conversation has (the scope panel, reviews, 插入到稿件) is asked as `talk == Talk::Library`, not as "not the paper's".

The chat is an agent loop (`ask` → `chat_step` → `run_tools` → `execute_tools` → `chat_step` …, at most `MAX_CHAT_STEPS` requests per question; before the last one the results carry `ai::LAST_STEP_NOTE`, telling the model to answer with what it has). `Chat::wire` is the conversation in the protocol's own messages and is append-only: the model's turns go back exactly as received (`ai::TurnReader` keeps thinking blocks and their signatures), and every tool call gets a result even when it did not run: refused by the person (`Chat::pending`, `Cmd::AnswerTools`), or stopped (`stop_chat`, which also keeps the text so far as the model's turn). Tools run on the background executor, each call with its own `Store` connection: a turn that only reads runs its calls side by side, one that writes runs them in order. `wisp_net::stream_chat` sends a request again, up to twice, when the service is busy (408, 409, 429, 5xx) or unreachable. Papers are named to the model by label (`P3`): `ai::resolve_labels` on the way in, `ai::add_labels` on the way out.

A question may carry pictures (`ChatItem::User::images`, pasted into the box or picked): `picture::prepare` makes each one a model takes (PNG, JPEG, GIF, WebP; scaled down when large), `ai::user_message_with` writes them the way each protocol wants.

The conversation with the library is the page 助手 (`Page::Ask`; it was 向文献库提问 until what it does outgrew the name; the paper's tab is still 提问). Before anything is said it shows what the assistant can be asked to do (`render_start` in `chat.rs`): cards by kind (找文献, 读文献, 整理, 写), two to a row whose lines are either a request sent as it stands (`Cmd::Suggest`) or a slash command left in the box for its words (`Cmd::StartCommand`, its description read off `ai::SLASH`). A card has a width of its own: one that shares the row's width is measured before its lines wrap. `Task::Chat` is labelled 助手 as well, and each task's row in 设置 › AI says which features use its model; a new feature that calls a model is added to that sentence.

Slash commands are the `ai::SLASH` table (name, description, what follows it, prompt template; an empty template is a command the window carries out, `/new`). `ai::slash_matches` is what the popup over the box offers; while it shows, `TextInput::choosing` hands Up, Down, Tab and Escape to `Workspace::chat_input`. A new command is one entry in the table. The person's own commands are `Settings::commands` (`ai::Command`: name, description, template; 设置 › AI › 命令), read after the built-in ones by `ai::read_input`, which therefore cannot be replaced; `{}` in a template is what follows the name, and a template without it takes what follows at its end. A question keeps what was sent for it (`ChatItem::User::prompt`, `Said::User::prompt`, empty when that is the text), so replaying a conversation does not read a template again; only a question from before that is expanded anew (`ai::expand_slash`, built-in commands only).

An answer is drawn as Markdown: `wisp_core::markdown::parse` (blocks and inline marks, rules ported from quiet.md; what does not close stays as written, since an answer is drawn while it streams) and `src/markdown.rs` (`render`). Citations like `[P3 p.5 "…"]` stay ordinary text; the chips under an answer come from `ai::citations`, the first `SOURCES_SHOWN` of them until `Chat::sources_open` holds the answer's index.

## 写作 (`write.rs`, `manuscripts.rs`, `write_find.rs`, `write_assist.rs`, `write_cite.rs`)

写作 (`src/write.rs` renders the editor and the candidates; `src/manuscripts.rs` the manuscripts; state in `Writing`): a library holds any number of manuscripts (`wisp_core::manuscript`: tables `manuscripts`, `manuscript_sections`, `section_snapshots`, with the `Store` methods in that file). A manuscript has a title, a language (`Writing::language`, a code of `manuscript::LANGUAGES`, default `en`) and ordered sections; a section has the person's name and a `kind`, a key of `structure::SECTIONS`, which is the part the candidates come from (`Writing::kind`; `other` for a review's own sections). A new one starts with IMRaD named in its language (`manuscript::imrad`). A section's text is saved as it is typed (`Workspace::write_typed`); a snapshot is kept `PAUSE_SECS` after the last key and on leaving the section (`write_snapshot`), only when `manuscript::worth_keeping`, at most `KEEP_SNAPSHOTS`; restoring one (`Store::restore_snapshot`) first keeps the current text. A removed manuscript is only marked (`removed_at`); a removed section goes with its snapshots, after a confirmation when it has text. Export (`manuscript::markdown`, `plain_text` for 复制全文, `docx`, a hand-written zip with stored entries) leaves out empty sections. The `drafts` table of earlier builds is emptied into one manuscript (`早先的草稿`) by `manuscript::migrate_drafts` on every open, so what an older build writes there comes in as another one; the schema version stays, since an older build reads the rest as before. Candidates are asked for, not looked up while typing (`src/write_find.rs`, `CandidateSearch`): the shortcut `write-find` (⌘↩ / Ctrl+Enter) or the panel's button searches for the selection, else the paragraph at the caret (`retrieval::paragraph_at`); the find box searches on Enter, its words as typed when they are plain Latin. Only the list of how each paper opens the part comes by itself (`write_openers`, when a part is opened), and texts read or sorted anew refresh only that list (`write_texts_changed`). What is written, in any language, is made by the translation model into three to five groups of search words in the sentences' language (`retrieval::queries_system` / `parse_groups`: content, rhetorical move, other wordings; cached per language and text in `CandidateSearch::made`), shown under the find box; without a model the words go as written and the panel says so. The part and the sentences' language are read through `Writing::kind` and `Library::sentences_language`. The `other` part is offered when some text has sentences there; the candidates can be narrowed to a tag or the starred papers, and a card unfolds into its neighbours. The model's part in the groundwork is a run like the screening one (`write_run_start` / `write_run_next`, `Task::Structure`): sorting asks about a text's outline (`structure::outline_prompt` / `parse_outline`) only for files whose rules left `OPEN_ENOUGH` paragraphs guessed, and `structure::merge` keeps the rules' labels where they were sure; reading sends each page of a file without text as a picture (`pdf::page_pictures`, `ai::read_page_request`), at most `READ_PAGES` per run, and keeps the text with `Store::save_read_pages`, which records who read it in `structures.text_by` and how many of how many pages in `pages_read` / `page_count`: a file read in part (`StructureInfo::read_in_part`) says so in the run's result and the detail panel, and the next run goes on from the first page not read. The actions on the paragraph being written are `src/write_assist.rs` (`Writing::assist`), on the selection or the caret's paragraph (`ai::paragraph_at`, `write_assist::target`), and of two kinds that the bar (`render_assist_bar`: groups a line apart, each button with a tooltip saying what comes back) and the card keep apart. Looking in the library changes nothing: 找句子 (`Cmd::WriteFind`, the candidates) and 配引用. A new version of the words is for the person to take or leave: 润色, 译成稿件语言, 仿写 (`ai::Assist::Rewrite`: rewritten after the library's sentences closest to the paragraph; when the candidates on show are not those, they are searched for first, `Assisting::awaiting`, and `write_rank` goes on with `assist_begin`; a paper drawn on is cited as `[@Key]`, `ai::Example::key`) and the person's own commands; `ai::assist_prompt` / `assist_request`, `Task::Chat`'s model, streamed with `wisp_net::stream_chat`. The result streams into a card over either page of the side panel, beside the original with the changed words marked (`ai::word_diff`; none for a translation or an own command); only the person replaces the paragraph (found again by its text, one step for `TextInput`'s Undo), inserts it below, copies or drops it. 配引用 (`src/write_cite.rs`, `wisp_core::citefind`, `Card::cite`) never shows a version of the paragraph: off the main thread, the translation model says what each sentence does and turns it into search words in the language of the library's papers (`citefind::plan_prompt`, so a Chinese paragraph finds English papers), the tool `find_citations` ranks the papers for each sentence, and the chat model says which of them bear it out (`judge_prompt` / `parse_judgement`); the card lists, under each sentence (with what it does as a small label), the papers with why and the sentence of their own that says so, the model's choices ticked and said to be 原始研究 or 综述 (without a model: all unticked). A paper that only restates the sentence is a line under it (`render_cite_hint`) naming the works it cites for it, and those the library holds are offered unticked (`Offer::via`); when the model chose nothing one line says so and 看相近的 opens what was found by words (`Found::leads`, `turn_rest`); the card ends with what was searched, and 插入 writes `[@Key]` at the ends of the sentences with `citefind::placed` and `replace_apart` (`Cmd::WriteCited`). One request at a time; a new part (`Assisting::leave`), library or request drops what is in flight. The manuscript's language is `Workspace::manuscript_language`, English until the manuscript carries one.

## 助手写 (`write_agent.rs`)

助手写 (`src/write_agent.rs`, state `Writing::agent`, an `Agent`; every command is `Cmd::Agent(Do)`; on while `Settings::agent_writing`): 写作's other mode, chosen by the two icons beside the outline's title (`render_mode_switch`: 自己写 / 助手写, named in their tooltips; among the manuscript's buttons while the outline is away, which is also when the manuscript's bar has 稿件 and a title set large). `render_write` then draws `render_write_agent`: the conversation `Talk::Write` in the middle (`render_chat`, with `render_agent_start` before anything is said) and the manuscript at the right (`render_manuscript_column`, which both modes share; here without the paragraph actions and the box of 改稿), the edge between them dragged like the others (`Edge::Manuscript`, `Settings::agent_manuscript_width`). The conversation is about the manuscript on show (`agent_attend`, called by `write_show`: another manuscript's is stopped and put away, this one's last is taken up) and kept under its id. `ask` adds `compose::note` to every question (`agent_note`) and gives the model the whole library, not the list on show; `run_tools` names the manuscript in calls that leave it out and does not ask about `edit_section` / `set_outline` on it; `run_tool` goes through `compose::call`. After a tool wrote a manuscript (any conversation's), `execute_tools` calls `manuscripts_synced`: the manuscripts are read again, the editor of the section on show takes each change with `replace_apart` (a step of its Undo each), a change elsewhere brings that section up (in this mode only), and what the sections read before the first change in answer to the question in hand is kept in `Agent::changed`. From that, `agent_marks` lights the changes of the section on show through `Revising::show`: a `Run` that is `told`, drawn by the same tints and margin bars as 改稿's and listed under the manuscript (`render_revise_run`: go to one, take one or all back, keep), and in the other mode by the box of 改稿 itself; a section written from nothing has the bar and no tint. The outline has a dot on a section so changed; the next question clears all of it (`agent_asked`). The versions of the section on show are stepped through over the manuscript (`render_version_stepper`, `Agent::versions`: the snapshots oldest first, the text as it is after the last; `agent_versions` reads them, `render_version` shows one in the manuscript's place, `Do::Restore` is `Store::restore_snapshot`). In a manuscript from a Word file each change leaves a comment (`comment_on_change_in`). A `Div` built with `flex_1()` keeps its basis of 0 under a later `flex_none().w(…)`: give such a column a parent of that width instead.

## 改稿 (`revise.rs`)

改稿 (`src/revise.rs`, state `Writing::revise`, a `Revising`; every command is `Cmd::Revise(Do)`): the box under the manuscript on the writing page. What the person writes there goes to `Task::Chat`'s model with the section (`wisp_core::revise::prompt`; what is selected is said to be what the wish is about), streamed with `wisp_net::stream_chat`. Unlike the paragraph actions, the changes are made in the manuscript as they arrive (`revise_take` → `revise_apply`: each block of the reply once it is complete, with `TextInput::replace_apart`, one step for the editor's Undo that leaves the person's caret where it was; the section's text before the first one is kept as a snapshot, `assistant`), and the window shows where: the place of the block being written breathes (`Run::target`), a change that lands has a tint run over its new words and settle (`Made::tints`, counted from `Made::since`), a bar stays in the left margin on its lines (`render_revise_bars`, by `TextInput::top_of`), and the editor scrolls there when it is out of view. `revise_marks` gives `render_write` the tints after the comments' marks and says whether any still moves, which is when a frame is asked for (`window.request_animation_frame`); nothing is animated by `with_animation` here, since the tint is painted by the editor. The changes keep their places while the text changes (`Revising::sync`, every frame and before every change of its own, through `revise::follow`); one whose words were changed by hand is no longer lit or taken back. The box lists the changes (`line`: what went and came, or the sentence around the new words): a row goes to its change and plays it again (`Do::Go`, `Do::Step`), 撤销 takes one back, 全部撤销 all of them and puts the wish back into the box, 保留 ends it; leaving the section ends it too (`Revising::leave`). In a manuscript from a Word file each change leaves a comment (`comment_on_change`).

## 批注 (`comments.rs`)

批注 and manuscripts from files (`src/comments.rs`, state `Writing::comments`, a `Commenting`; every command is `Cmd::Comment(Do)`): the panel beside the manuscript has three pages (`render_side_switch`; `Writing::side`, a `Side`, `Cmd::WriteSide`), 候选句, 批注 and 参考文献; a section's pill or outline row counts its open comments. `comment_marks` gives the editor the ranges to tint (`TextInput::set_marks`, set in `render_write` every frame, so they follow the text) and `render_comment_markers` a marker in the editor's right margin per line where commented words begin, placed by `TextInput::mark_tops` (where the last frame drew each mark; a frame that moves them asks for another). A click on tinted words (`InputEvent::MarkClicked`, `comment_mark_clicked`) or a marker shows that comment's card (`comment_point`: the panel turns to 批注, `Commenting::focused` stands out, `comment_reveal` scrolls to it once the list has been drawn); the marker's click is `Do::Show`, which also selects the words and scrolls to them (`TextInput::top_of`, `Writing::editor_scroll`). While 写作 is the page the library's sidebar is the manuscript's outline (`render_outline` in `manuscripts.rs`, `Workspace::outline_shown`): its sections with length and open comments, and the section pills over the editor are left out; `Cmd::WriteNav(true)` (its top row) shows the library's navigation instead until 写作 is opened again (`Writing::library_nav`). `comment_review` asks `Task::Chat`'s model about the section or the selection with `wisp_net::complete`, hands it the open comments of others to answer, and a new review takes the place of the last one's remarks that still wait. `Do::Take` / `Back` change the text with `replace_range` (one step for the editor's Undo) and the comment with it. In a manuscript that came from a Word file, replacing a paragraph with an assist result leaves a comment (`comment_on_change`). `import_manuscript_files` reads off the main thread (`take_file`); a dropped .docx is a manuscript on any page, .md and .txt on the writing page. 稿件's menu also lists the reviews the assistant wrote sections for (`reviews_written`, `review_into_manuscript`, the sources of that conversation's transcript for its citations). Export: `ManuscriptExport::Docx` / `DocxTracked` through `Workspace::manuscript_word`; the author is `Settings::author_name` (设置 › 通用 › 写作).

## Citations and 出处 (`cite.rs`, `write_source.rs`)

Citations in 写作 (`wisp_core::cite`, window side `src/cite.rs`, state `Library::citing`): written in Pandoc's form `[@Zhang2024]` (`[@A; @B]`, with locators), so a draft and its exported Markdown stay plain text and Pandoc formats them with the BibTeX of the cited papers (`cite::bibtex`, same keys, through `export::bibtex_keyed`). A key is first author + year (`DeNovo2020` from the title without authors, `-nd` without a year), a letter for the second paper with the same key; `cite::Index` gives them in the order papers were added, so a new paper never takes an earlier one's key, and a key once cited is kept in `cite_keys` (`Store::keep_cite_key`) so it stays with its paper when the record changes or another is deleted. `cite::find` resolves every citation of a text (`Found`: paper, trashed, removed, unknown, or ambiguous for the old `(Zhang et al., 2021)` form, which is still read and `cite::upgrades` rewrites into keys); `cite::references` is the list in author-year order, `reference_list` / `reference_markdown` its text. Functions take text, one section or several, never the drafts table. 引用 (`Cmd::WriteCite`, a paper id) inserts the key; the reference list is the third page of the panel beside the manuscript (`render_references`): of the part or the whole manuscript, it leads to each paper, says in the whole manuscript's list which sections cite it, points out what does not resolve (a dot on the page's tab), and offers any paper of the library by typing part of it (`Index::matching`). The outline's row 参考文献 (`Cmd::WriteReferences`) shows the whole manuscript's list, and a manuscript read through ends in it (`render_references_read`), which is where that row scrolls to then. What the manuscript cites is worked out once a frame, before the outline and the page are drawn (`cite_refresh` in `render_library`, kept in `Citing::listed`); the tab, the row and the page read that and build no index of their own.

出处 (`src/write_source.rs`, state `Citing::sources`, a `Sourcing`; every command is `Cmd::Source(Do)`): `cite::Listed::standing` is every citation of the manuscript with the passage kept for it (`standing`, a `Standing` with its `Rests`), worked out by `cite_refresh` with the rest. On the reference page beside the manuscript each entry has under it the passages its citations on show rest on (`render_passages`: the paper's whole sentence, part and page, a sparkle on one a model found, in the warning colour a citation whose paper does not bear it out), and a click is `Cmd::GotoSource` with the page and the sentence, which the PDF highlights. With the caret in a citation a line under the manuscript (`render_source_strip`, over the box of 改稿) names the paper and shows that sentence's passage, or the sparkle that looks for it; on the reference page its entry is brought into view once (`source_follow`, the list's `ScrollHandle`) and the passage is lit. A passage is kept when the person cites from a sentence: 引用 on a candidate is `Cmd::WriteCiteFrom` (`cite_paper` with the candidate; a sentence that cites the paper already is not made to cite it twice, the passage is kept for the citation there), 配引用's 插入 keeps each ticked paper's own sentence, and an answer put into a manuscript (`sources_quoted`, from `insert_into_section` and `draft_to_manuscript`) keeps the sentences it quoted where `ai::locate_quote` finds them. The sparkle over the list (with how many citations have none) is a run off the main thread (`sources_find` → `work`): `Task::Translate`'s model makes search words of the citing sentences (`citefind::words_prompt`), the tool `find_passages` looks through each cited paper once, and `Task::Chat`'s model chooses, `AT_ONCE` citations a request; what it finds is kept as it comes (`Store::keep_passages`), at most `passage::MAX_ASKED` a run, and a toast sums it up. Without a model the nearest sentence is kept when `fair`; a paper with text and not a sentence sharing a word is kept as not bearing the citation out. The × on a passage's line lets go of it. An entry's own row and each passage's line are separate elements: a click handler on a parent would hear the child's click too.

## The manuscript editor and text fields (`input.rs`)

The manuscript editor draws Markdown as it says (`TextInput::markdown`, like quiet-md's editor but keeping the text as written): `wisp_core::markdown::lines` reads each line with its pieces and where their syntax is (`Piece`, `Part`; `inline` is built on the same reader), `shape_markdown` in `input.rs` shapes one row per line (headings larger, emphasis, code, links and `[@Key]` citations in their style, a dot for `-`, quotes behind a bar, a ground for fenced code, a line for `---`) and hides the syntax except on the lines the selection or caret is on (held while the button is down). `DisplayMap` is how drawn offsets stand to the text's bytes; every hit test, caret, selection, IME rectangle and comment tint goes through it. Enter in a list or quote goes on with it (`markdown::continued`), on an empty item ends it. A section's text is therefore Markdown everywhere: `manuscript::section_markdown` (headings written in a section go under the section's) is the export and what 通读 and the versions draw, `markdown::plain` is the clipboard's and a Word file's text, a new Word file gets the bold, italic and headings (`word_paragraph`), and a Word file's paragraph that would read as Markdown comes in escaped (`escape_markdown`).

What a click selects in a text field is `wisp_core::selection`: two clicks a word (ICU4X's `icu_segmenter` with its dictionaries, so Chinese and Japanese come apart into words; single Han characters next to each other, an unknown term, are taken together up to a word in `JOINING`; a `[@…]` citation is one word), ⌘ / Ctrl with a click the sentence (`citefind::whole_sentences`: cut as 配引用 cuts, but a semicolon goes on), three the paragraph (the line without its quote, marker or hashes). `TextInput::grain` keeps the unit, and a drag after the press grows the selection by it (`selection::extend`). A masked field selects all.

`input.rs` is the app's own text input (single / multi-line, IME via `EntityInputHandler`; a field that `accepts_images` hands pasted pictures to its owner; Cmd/Ctrl+Z and Shift+Z undo and redo, letters typed in a row being one step; `replace_range` is an owner's change as one step); `pdf.rs` renders pages with `hayro` on a worker thread into a virtualised list, keeping a bounded number of pages.

## 综述

综述 (`wisp_core::review`, window side in `src/chat.rs`): `/review` gives the conversation with the library a record (`review_projects`, one JSON body with a `revision`; `review_conversations` ties it to its conversation, and it goes with it: `Store::remove_conversation`, and the schema batch clears one left behind). `Review::step` is where it stands (1 the requirements, 2 the framework, 3 the outline, 4 writing); `ReviewAction` is every change, applied by `Store::apply_review` against the revision the caller read. The outline comes in two stages, after gzd-review-writing's F0 → F1: `Review::framework` (初步框架) is what the reviews already published make of the topic and the chapters proposed from them, a starting point nothing has borne out; the outline is then built against it from the library's own papers, chapter by chapter (kept, merged, split, dropped, new, and which papers made it so). The person may go on without a framework (`ReviewAction::SkipFramework`, only while none is recorded), and a record from before it, which has an outline and no framework, counts as one that did (`Review::framework_settled`). A framework worded anew asks for its confirmation and the outline's again. Only the person advances it: the requirements, the framework and the outline are each recorded (an answer, or what is selected in one: `Cmd::Review(ReviewDo, text)`) and then confirmed, and no section is kept before the outline is. Where a step's text is still to come, the bar over the conversation offers the request that asks for it (`Cmd::Suggest`). A section kept (`ReviewDo::Section`, `section_of`) brings its evidence: `review::cited_evidence` makes a row of every citation (the sentence the citation closes, the paper behind the label, page, quotation), added once and unjudged; `Library::load_review` reads the record into `Chat::review` and looks the quotations up with `ai::check_quote` (`Chat::review_checks`) whenever the conversation, the record or the papers change, so drawing asks the store nothing. Whether a source bears a claim out is the person's (`EvidenceJudgment`, `Cmd::JudgeReviewEvidence`); a judgment keeps `Store::evidence_fingerprint` (title, abstract, the text of the page named) and stands while that and the claim's sentence do (`Review::linked`, `source_current`). There are no triggers and no version bump for any of this: `store::UNRELEASED_VERSION` is what builds between 0.5.0 and the next release wrote, and the schema batch drops what they left. The record is shown in place of the conversation (`Chat::review_open`, `render_review_record`), each text of it changed in `Modal::ReviewText`, a row in `Modal::ReviewEvidence`. A question of such a conversation carries `chat::review_note` (the step and what it asks of the model, the requirements, the framework until the outline is confirmed, the outline, the sections by name), never the sections' text. `review_to_manuscript` makes a new manuscript of the sections; `cite::convert_ai_citations` turns `[P3 p.5 "…"]` into `[@Key, p. 5]`, leaving the quotation in the record.

## 图片库 (`figures.rs`)

图片库 (`src/figures.rs`, state `Library::gallery`, a `Gallery`): its entrance is 收藏. The sidebar's 收藏 row counts the starred papers and the figures and is lit on either page; `render_collection_switch` (文献 / 图片) stands at the top of the starred papers and of `Page::Figures`. The page is a `uniform_list` of rows of cards (`grid` decides the columns), searched by `Gallery::search` and narrowed to one of the figures' own tags (`Cmd::FigureTag`). A card's picture is read and scaled down off the main thread when its row is first drawn (`figure_thumb`: `THUMB_WORKERS` at a time, `KEEP_THUMBS` kept, the rest dropped with `cx.drop_image`). In the PDF viewer a piece cut out has 收藏到图片库 beside 用这张截图提问 (`PdfView::collect_cut` → `PdfEvent::Figure`, a `Piece` with the caption read off the page); the piece stays marked until the figure is kept (`cut_kept`), and cutting stays on for the next one. `Modal::Figure` (a `FigureForm`) is both that dialog and the one a card opens: the picture at the left (`Gallery::large`, let go of by `tend_figure_dialog` once no figure's dialog is open, however it was closed), 图号 / 图注 / 标签 / 备注 at the right. It is opened from an event without a window, so its fields do not submit on Enter and the first frame gives one the keyboard. The sparkles by 图注, 标签 and 备注 (`Cmd::FigureInfer`, no words on them by the person's wish: a tooltip says what each does) send the picture to `Task::Chat`'s model with `ai::picture_request`; the answer goes into the field with `replace_range` (one step to undo: the number only into an empty field, tags added to those there, a reading after the notes there) and nothing is kept before 收藏 / 保存. 打开原文 (`Cmd::FigureSource`) is `GotoSource` plus `PdfView::go_to_place`; the detail panel stands beside the figures as beside the papers. 生成图片 on the page (`Cmd::DrawFigure`) opens the same dialog with a box under its empty stage (`FigureForm::draw`, a `Drawing`: the description, the shape, `run` counting requests and stops): `Cmd::FigureDraw` sends the description to `Task::Image`'s model off the main thread (`draw_figure`), the picture that comes back is the dialog's (`form.png`), drawn again at will and kept only by 收藏, as a figure without a paper. With it the tags get `DRAWN_TAG` and the notes say which model drew it from what, unless the person wrote notes of their own; such a figure offers neither 打开原文 nor 用这张图提问.

## 提取 (`extract.rs`)

提取 (`src/extract.rs`, state `Library::extract`, an `Extract`; every command is `Cmd::Extract(Do)`): `Modal::Extract` (a `Form`) picks the fields for the marked papers (`MenuKind::Papers`, also one paper's menu) or the list on show (自定义词条's 让助手填写…, the page's button) and says how many papers will be read (`Library::extract_plan`). The run mirrors the screening one (`extract_start` / `extract_next`: `Task::Screen`'s model, `Settings::screen_workers` at a time, `run` bumped by a start or stop, `GIVE_UP` failures in a row end it, a paper with nothing to read is counted and not asked about) and shows in the sidebar while under way. `Page::Extract` (its nav row stands between 筛选 and 写作 in the sidebar, with the number waiting) lists `Library::extract_rows` as a `uniform_list`, one row per paper and field; `Do::Apply` writes the ticked rows on show and `Extract::last` keeps what the fields held (or what was set aside) for `Do::Undo` until the page is left. The keys reach it through `screen_key` and `nav` (`extract_key`, `extract_nav`). In the detail panel `render_field_rows` draws each field with a bare sparkle (`Do::Ask`: that one field of that paper, whatever was said before); the answer waits under the field for 采纳 (`Do::Take`) or 忽略, and under a value that came from a proposal its sentence stays, leading to the page. The detail panel has no text field for a custom field, so nothing goes through `replace_range` here.

## 筛选 (`screen.rs`, `screen_single.rs`, `screen_confirm.rs`)

筛选 has three faces (`Screen::mode`, a `ScreenMode`; `Cmd::ScreenMode`): 批量 is the queue as a list with the assistant's run over it (`src/screen.rs`); 逐篇 is one paper at a time (`src/screen_single.rs`: a rail of the round's papers with what became of each, the paper with the assistant's suggestion and its abstract, the four decisions under it; a decision brings the next paper up, past the last one the round is summed up; `Library::round_paper` is the paper on show, which is not `Library::selected`: the detail panel opens beside it only when asked, Enter or `Cmd::ScreenBeside`, and then follows the round); 确认 is the suggestions for the waiting papers looked over and written together (`src/screen_confirm.rs`: a row per paper with the status it will get, ticked unless left out; what is on show is written by `Cmd::ConfirmApply` and can be taken back, `Screen::confirmed`). A finished run of the assistant leads to 确认; it cannot be entered while a run is under way. `Workspace::render_advice` draws a suggestion in full in all three, and `Cmd::ScreenAskOne` asks the assistant about one paper (`screen_start` with `only`). The keys are fixed bindings in the context `Workspace && !TextInput` (`shortcuts::rebuild`, listed read-only in 设置 › 快捷键 from `SCREEN_KEYS`) that end in `Workspace::screen_key`: about the round's paper, the paper open in the queue, or the row the keys are on. The arrow keys there go through `Workspace::screen_nav`, and Esc leaves a round or the confirmation for the queue. A row of a `uniform_list` needs `w_full()`, or it is as wide as its content.

## 自定义: connectors and skills (`custom.rs`)

自定义 (`src/custom.rs`, 设置 › 自定义; every command is `Cmd::Custom(Do)`): what the person adds to the assistant. 连接器 are MCP servers (`Settings::connectors`, a `connector::Connector`: a name, a target and a token): a target that begins `http(s)://` is asked over Streamable HTTP with the token as a bearer (after `initialize`, in the protocol revision the server answered with), anything else is a command started through the person's login shell (`cmd /C` on Windows) that speaks on its standard streams. An address whose post of `initialize` is answered 400, 404 or 405 is a server of the transport before Streamable HTTP (2024-11-05, the `…/sse` addresses many services still give, as the 2025-03-26 revision has clients fall back): `mcp::Sse` opens the event stream there with a GET, posts every message to the address its `endpoint` event names (`connector::endpoint`: on the same origin only, since the token goes along) and reads the replies, and the pings it answers by post, off the stream (`connector::Events`, a reader thread feeding a channel as for a command); both HTTP links send the token and refresh the sign-in through `mcp::Auth`. `wisp_core::connector` has the messages and how replies are read, `wisp_net::mcp` the three transports and the open connections (`tools` connects anew and lists, `call` connects once more when a connection broke, `keep_only` closes the rest, `disconnect` one; both say `mcp::Failure::SignIn` apart from other failures). A connector is connected to at start, by its switch and by 连接, never while its fields are typed (a command half written is not run); where each stands is `Workspace::connections` (`custom::Connection`). A remote connector without a token of its own is signed in to in the browser (OAuth 2.1 with PKCE, as MCP's authorization spec has it): `wisp_core::oauth` is the side without sockets (reading `WWW-Authenticate`, where protected resource and authorization server metadata are looked for, the registration body, the authorize address, token forms and how answers are read, the loopback's callback, the file), `wisp_net::oauth` asks it: `begin` probes the server, finds its metadata (or, for a server from before RFC 9728, its origin's), registers the app as a public client (reusing the client of last time while its loopback port is free) and opens the loopback on `localhost`; the window sends the browser to `SignIn::address` (a scripted run prints it as `sign-in: …` instead), and `SignIn::finish` waits for the callback (`WAIT`, or until `custom::Stop`), exchanges the code and answers the browser with a page that says how it went. The sign-ins are kept by address in `oauth.json` beside `settings.json` (plain text like the model keys, mode 600 where there is such a thing), read and written under one lock; `bearer` is the token a request carries, refreshed first when within `oauth::MARGIN_SECS` of running out, and a 401 is refreshed once (`renew`) before it becomes `Failure::SignIn`; a refresh the server refuses ends the sign-in and keeps the client, one that fails otherwise keeps both. 连接 asked for by the person goes on to the sign-in by itself, a connection at start only says one is wanted (需要在浏览器中登录, with 在浏览器中登录); 退出登录 forgets the tokens and gives them back to the server's revocation endpoint, and removing a connector forgets its sign-in unless another uses the address. A server whose authorization server takes no registrations cannot be signed in to this way: its token goes into 令牌. `cargo run -p wisp_core --example mock_connector -- 8790 [seconds]` is a server that wants a sign-in (`http://localhost:8790/mcp`), with a consent page and tokens good for the given seconds. 技能 are folders with a `SKILL.md` under `skills/` beside `settings.json` (`wisp_core::skill`: front matter `name` and `description`, then the instructions; `Settings::skills_off` are those switched off), read at start and when the page is opened (`Workspace::skills`); a skill is words only, nothing in its folder is run. Both reach the assistant in `chat_step` as tools after the library's (`Workspace::outside_tools`, `ai::chat_request_with`): a connector's tools as `<slug>__<tool>`, and `use_skill`, whose description lists the skills on. `run_tools` looks a call up with `outside_call` (`PreparedCall::outside`); a connector's tool that does not declare `readOnlyHint` is asked about before it runs, on the same card as the tools that change the library, with its arguments as the details. `wisp` and `wisp mcp` know nothing of either.

## Settings (`settings.rs`)

`settings.rs` is the settings view (通用, 外观, 快捷键, AI, 自定义, 网络, 关于). The AI page has three tabs (`AiTab`, `Cmd::AiTab`): 模型 is the providers in a list at the left and the one picked at the right with its models (`ProviderFields`, made anew for the provider on show; a model added keeps them, so the field keeps the keyboard), 任务 which model each task uses with its instructions (the translation prompt), 命令 the person's own commands. A provider's mark is `assets/icons/provider-<preset>.svg` (from lobe-icons, see THIRD_PARTY.md) on a tile of `theme::provider_tile`. The 任务 cards are given their width in pixels (`column_width`): under shares, the column leaves a gap under the card with the prompt. It replaces the page while `Workspace::settings_view` is `Some`; the open library stays underneath. There is no save button: each change writes `settings.json` at once.

Every page stands in one frame, `AI_COLUMN_W` wide and centred; a narrower page (`COLUMN_W`) keeps to the frame's left, so the left edge is the same on every page. 返回 is in the window's top-left corner, as the library's way back is. The font picker on 外观 (the 界面字体 button, the search field, the names in the list) is set in `theme::UI_FONT` whatever font is chosen, with a sample in the font itself beside each name: a font that draws letters as pictures would otherwise hide its own name and what is typed.

A wrapping `TextInput` under ancestors whose widths are all percentages (the settings column) is measured at 240px; give its wrapper a pixel width there, as `ai_page` does for the translation instructions.

## Background and the release check (`background.rs`)

Background (`src/background.rs`): while `Settings::keep_running` is on (设置 › 通用 › 后台, the default), the window's close button does not quit: macOS hides the app (the Dock icon brings it back through `on_reopen`), Windows hides the window behind a tray icon (`tray-icon`; 打开 / 退出) and a second launch for the same settings file brings that window up (`hand_over`, a marker file in the temp folder) instead of starting again. The window and its runs stay as they were. macOS has an app menu for it (⌘Q, ⌘H; `background::set_menus`, made again when the language changes); Linux closes as before.

The release check (`check_update`) reads the redirect of GitHub's `releases/latest` (the JSON API is rate-limited per address). It only notifies and opens the release page: nothing is downloaded or installed.

## PDF import

PDF import is a run (`Library::import`, an `ImportRun`): a folder dropped or picked (添加文献 › 导入文件夹…) is expanded by `import::folder_pdfs`, each folder between it and a PDF becoming a tag of that paper (merged into a paper already held); `import_paths` reads `IMPORT_WORKERS` files side by side (and `extract_missing` re-reads up to `READ_WORKERS` full texts at once), `add_pdf` adds a row for each, the sidebar shows the progress and then the summary until it is put away, `Modal::ImportReport` the rows. One file alone is a toast instead.

## Keyboard, right button and selection (`context.rs`, `select.rs`)

The keyboard and the right button (`src/context.rs`): the arrow keys, Page Up/Down, Home/End, Enter and Delete are fixed bindings in the `Workspace` context (`shortcuts::rebuild`) that end in `Workspace::nav`: in an open menu they move along its items, else they move in the papers on show (全部文献 and 筛选; left and right turn the pages of a PDF on show, else move a screenful), Enter opens the PDF, Delete or ⌘⌫ moves the paper to the trash and the one that takes its row is selected. A text field with the keyboard hears them first; a one-line or empty field passes Up and Down on. A right click is `.on_mouse_down(MouseButton::Right, self.on_context(MenuKind::…, cx))`, its items in `context_menu` (`Menu::breaks` are the lines between groups, `Menu::paper` the row marked meanwhile): papers, trashed papers, files, tags (rename and remove: `Workspace::retag`), past conversations, answers.

Several papers at once (`Library::marked`, 全部文献 only): a click with ⌘ / Ctrl adds or takes one (`Workspace::mark`), with Shift the stretch from `Library::anchor`; Shift with an arrow moves `Library::cursor`, ⌘A marks the list on show, Esc lets go. More than one marked puts the detail panel away, and showing one paper (`select`) ends the marking. A right click on a marked row is `MenuKind::Papers`; its commands end in `Workspace::run_batch` (`AskPapers`, `StarPapers`, `ReadPapers`, `TagPapers`, `FindPdfsOf`, `AskTrashPapers` / `TrashPapers`). `AskPapers` starts a new conversation with the library about those papers alone: `Library::asked`, read through `Library::scope_papers` wherever the scope of a library question is shown or built, and emptied by the next new conversation.

Text that is not an answer or a field is selected through `Workspace::selectable(key, text, cx)` (`src/select.rs`, `Workspace::picked`): drag, double click for a word, triple for all, ⌘C or a right click to copy. While the button is held a layer over the window follows the pointer, as for the edges. Use it for any text a reader may want to copy.

Selecting in an answer: `markdown::render` takes a `Selecting`, keeps the `TextLayout` of every piece it draws and reports where the pointer is as a `Place` (piece, byte); the selection is `Chat::picked`, its text `markdown::text_between`.

## Layout: panels, sidebar, list head, reading mode

The detail panel's width is `Settings::detail_width` (0 is `DETAIL_W`), dragged by its left edge (`detail.rs`). An element only hears the pointer moving over itself, so while an edge is held (`Workspace::resizing`, an `Edge`) a layer over the whole window takes the moves (`home.rs`); do the same for any other drag. A tap is over before that layer is drawn, so each edge also hears its own mouse-up.

The library's sidebar is `Settings::sidebar_width` (0 is `SIDEBAR_W`) and `Settings::sidebar_hidden`: its right edge is dragged (`Workspace::drag_sidebar`; pulled in past half of `SIDEBAR_MIN` it is put away, back out and it returns), clicked twice it is put away, and `Cmd::ToggleSidebar` (the button at the top left, the shortcut `sidebar`) puts it away or brings it back. Widths are computed from `Workspace::sidebar_width`, never from the constant. Its rows are three groups (`render_sidebar`): the views of the one list of papers (`VIEWS`: 全部文献, 最近添加, 未读, 收藏, 缺 PDF), then the pages where the work is done, 助手 and a review's path in its order (检索与导入, 筛选, 提取, 写作), then the tags, and under the line what is managed (自定义词条, 回收站, 设置). A number is shown only when it is above 0. What waits for a decision is 筛选's number and the 收录 filter, not a view. The two top-left buttons (`render_corner`) are drawn in the sidebar or, while it is away, over the list at the same place, level with macOS's traffic lights. Its arrow is the only way back in the sidebar and goes up one level: 文献库 from a manuscript's outline (`Cmd::WriteNav(true)`, which also brings a sidebar that was put away back, since the library's navigation is the sidebar), 文献库 from the narrow list beside a paper asked about (`Cmd::LeaveAsk`), 所有文献库 from the library. 设置 has its 返回 in the same corner.

The head of the paper list (`render_papers`) keeps its height (`papers_head`) however narrow the list is. Under `roomy` the three buttons are `ui::tool_button`s (the icon, the words in a tooltip, `ui::tip`) and the search box says only 搜索…. The filter chips are measured (`shape_line`); where they do not all fit the row is folded: the set ones first, as many as fit, `+N` for the rest. Under the pointer a card with all of them lies over the row and the list (`Workspace::filters_over`: the row's hover and the card's; `Menu::filter` keeps it under a filter's choices), drawn as the column's last child, its first chips where the row's are, shown after a moment by its animation. `filters_drawn` forgets the pointer in a frame that does not draw the folded row, since `on_hover` only says a change.

Reading mode (`Library::reading`, `Cmd::ToggleReading`: the button on the PDF's toolbar, the shortcut `reading`, Esc to leave before Esc closes the paper): `detail_width` is then the window's and `render_library` draws the detail panel alone, with a one-line header and no left edge. Nothing is made anew, so `Library::pdf` keeps its place and `paper_chat` its conversation and unsent text; leaving the paper, changing the page or the search shortcut ends it. The conversation's width beside the PDF is `Settings::chat_width` (0 is a share of the panel; `Workspace::chat_width`, `split_chat_width` in `library.rs`), dragged by the edge between the two (`Edge::Split`, `drag_split`).

## Asking about a paper and the floating conversation (`library.rs`, `floating.rs`)

Asking about a paper lays the window out for it (`Workspace::asking`, in `library.rs`): the sidebar is away, the papers on show are a narrow list at the left (`render_ask_list`: the corner's two buttons, the search box, a two-line title and a line of details per paper; `Settings::ask_list_width`, 0 is `ASK_LIST_W`, dragged by the detail panel's left edge), and the conversation with the paper's PDF to its right has the rest (`detail_width`). Nothing is stored for it: it follows from 提问 being the tab and `Library::split` (on by default; `Cmd::BesidePdf`, the x on the PDF's bar puts the PDF away and so ends it for the papers after as well, 对照 PDF brings it back). Beside the list the paper's one-line header is the title strip itself (`in_strip` in `render_detail`; on Windows it stops short of the window's buttons), so 退出提问 is level with the list's arrow. `Cmd::LeaveAsk` (Esc before Esc closes the paper, 退出提问 in the one-line header, the list's ← 文献库, the sidebar's button or shortcut) goes back to the tab it was come to from (`Library::ask_from`). On a page whose list is not the papers' (筛选, 助手, 写作), or in a window narrower than `ASK_LIST_MIN` + `detail::SPLIT_MIN`, there is no list and the paper has the window. A paper without a PDF keeps the layout, with 添加 PDF / 查找开放全文 at the right, so the arrow keys do not change the layout from paper to paper. The table and the narrow list share `Library::table_scroll`; `render_library` scrolls to the selected paper when the layout changes (`Library::ask_drawn`), and row heights come from `Workspace::row_height`. A citation followed from that conversation, a passage or a picture sent from the PDF, all end there.

The paper's conversation can float over its PDF instead (`src/floating.rs`, `Settings::floating`, the geometry in `wisp_core::floating`): where the conversation would stand beside the PDF, the PDF takes the whole panel and the same `Chat` and input are drawn in a window over it (the PDF's bar of tools stays clear). The title bar moves it, the bottom-right corner sizes it (`MIN_WIDTH` / `MIN_HEIGHT`), 分栏 goes back beside, the minus folds it into a round button that a drag moves and a click opens (`is_drag`: farther than `DRAG_SLOP`). Place, size and folding are saved; `fit` keeps what is drawn inside the area, which is measured as it is drawn (`Library::float_area`), and leaves the stored place alone, so a window grown back finds it. A held title bar, corner or button is `Library::float_drag`, heard by a layer over the whole window (`render_float_layer`, drawn in home.rs) like the edges. The window and button `occlude()`, so the PDF under them hears neither wheel nor press while the rest of it scrolls and selects as before. A passage or picture sent from the PDF opens a folded conversation (`unfold_chat` in `show_paper_chat`). The switch to floating is 悬浮 in the conversation's header (`render_float_switch`).

## PDF view (`pdf.rs`)

`PdfView` draws pages at `Zoom` (fit width, fit page, or a percentage of the page's own size). `resize` is the one place that changes what decides the page size and keeps the point under an anchor where it was; pages are rendered at `render_scale` (a few steps, within `MAX_PAGE_PIXELS`) and kept within `KEEP_BYTES`. The wheel is heard in the capture phase by a canvas under the list (`PdfView::wheel`), since the list would scroll before a parent could zoom.

Selecting in a PDF: the worker hands out a page's glyphs (`pdftext::page_marks`, after the page is drawn), `PdfView` keeps a `Selection` of them on one page (`mark_at`, `mark_boxes`, `marks_text` in core), and tells its owner through `PdfEvent` (copied; a passage for a conversation, kept in `Chat::quotes` and written into the question as `[P3 p.5 "…"]` by `ai::quoted_passage`; a piece of a page cut out as a picture; a passage to translate). 翻译 puts a card by the selection (`card_place` keeps it in view): `Workspace::translate_passage` goes through `translate_text` (`src/translate.rs`), the same path and cache as the title and abstract and the batch, and `sync_pdf_translation` hands the state back (`PdfView::show_translation`). Its menu asks one of `Settings::profiles()` for this once, without changing the settings, and that answer replaces the kept one (`Store::replace_translation`; the cache key has no model in it); `Library::translation_asks` drops an answer that a later request for the same text overtook.
